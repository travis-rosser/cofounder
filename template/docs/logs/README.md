# Session logs

What happened on the bigger days. Not a transcript. A handoff, written so a session that
was not there can pick the work up.

Write one when a day materially changes direction, architecture, or shipped behavior, or
produces hard-won operational understanding. Skip it for ordinary work. Most days need
nothing.

Naming: `YYYY-MM-DD-short-description.md`. Start from `SESSION-LOG-TEMPLATE.md`. Copy it,
do not edit it.

**Add the log's line to the index below in the same change that writes the log.** The index
is the point: it is how a later session finds the one day that matters without opening
twenty files. A log nobody can find is a log nobody reads.

Logs are never edited after the day they describe and never deleted. They are the only
place the lessons that cost you something live. If a log's conclusion later turns out to be wrong, that
is a new log or an ADR, not a correction to the old one.
