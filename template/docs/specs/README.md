# Feature specifications

One dated design doc per feature, with a matching `-plan.md` where the build needed one.
This is the "spec → plan → code" step made durable, so the reasoning behind a feature
survives the session that built it.

Naming: `YYYY-MM-DD-short-description.md` and `YYYY-MM-DD-short-description-plan.md`.

Start from `SPEC-TEMPLATE.md` and `PLAN-TEMPLATE.md`. Do not edit the templates to
write a spec. Copy them.

Mark status `Draft` until accepted. `Draft` means "not yet committed behavior", and an
agent should treat it that way. Keep the lists below current; they are the index.
